# Feature Specification: 视频制作流程管理应用

**Feature Branch**: `001-video-workflow-app`
**Created**: 2026-01-26
**Status**: Draft
**Input**: User description: "视频制作流程管理应用，包含草稿管理、资源预览、视频处理等功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 草稿与资源管理 (Priority: P1)

用户打开应用后，可以看到所有草稿列表。选择一个草稿后，右侧显示该草稿包含的所有资源（源视频、角色图片、提示词、分镜视频等）。用户可以点击任意资源进行预览：文字资源可编辑，图片资源可查看，视频资源可播放。

**Why this priority**: 这是应用的核心交互基础。没有草稿和资源管理，其他所有功能都无法使用。

**Independent Test**: 可以通过创建草稿、添加不同类型资源、预览资源来完整测试，无需依赖其他功能。

**Acceptance Scenarios**:

1. **Given** 应用启动, **When** 用户查看主界面, **Then** 显示草稿列表（如无草稿则显示空状态提示）
2. **Given** 存在多个草稿, **When** 用户点击某个草稿, **Then** 右侧显示该草稿的所有资源，按类型分组展示
3. **Given** 选中草稿包含文字资源, **When** 用户点击文字资源, **Then** 显示编辑面板，可修改内容并保存
4. **Given** 选中草稿包含图片资源, **When** 用户点击图片资源, **Then** 显示图片预览
5. **Given** 选中草稿包含视频资源, **When** 用户点击视频资源, **Then** 播放视频，支持拖动进度条、暂停、静音

---

### User Story 2 - 视频分镜切分 (Priority: P2)

用户选择源视频后，可以一键将其自动切分为多个分镜源视频。系统调用已有的 video_splitter 工具进行场景检测和切分。切分完成后，分镜源视频列表自动更新。

**Why this priority**: 分镜切分是后续视频处理（高清化、对口型、合成）的前置步骤，但需要先有资源管理功能。

**Independent Test**: 可以通过上传源视频、执行切分、验证生成的分镜文件来完整测试。

**Acceptance Scenarios**:

1. **Given** 草稿中有源视频, **When** 用户点击"切分"按钮, **Then** 系统开始分析视频并显示进度
2. **Given** 视频切分进行中, **When** 用户查看进度, **Then** 显示当前处理进度（百分比）
3. **Given** 视频切分完成, **When** 用户查看资源列表, **Then** "分镜源视频"区域显示所有切分出的视频片段

---

### User Story 3 - 视频高清化 (Priority: P3)

用户可以选择单个或多个分镜新视频，批量进行高清化处理。系统调用已有的 video_upscaler 工具提升分辨率和帧率。高清化完成后，高清分镜新视频列表自动更新。

**Why this priority**: 高清化是视频质量提升的关键步骤，但依赖于先有分镜新视频。

**Independent Test**: 可以通过添加分镜新视频、选择批量高清化、验证输出视频质量来完整测试。

**Acceptance Scenarios**:

1. **Given** 草稿中有分镜新视频, **When** 用户选择一个或多个视频并点击"高清化", **Then** 系统开始处理并显示进度
2. **Given** 存在多个分镜新视频, **When** 用户点击"全部高清化", **Then** 系统批量处理所有分镜新视频
3. **Given** 高清化处理完成, **When** 用户查看资源列表, **Then** "高清分镜新视频"区域显示处理后的视频

---

### User Story 4 - AI 角色图生成 (Priority: P4)

用户选择源角色图片后，可以调用豆包 API 生成新角色图片。用户还可以从任意视频中截取画面作为源角色图片。

**Why this priority**: AI 角色生成是创意功能，增强用户体验，但不是核心流程的必需步骤。

**Independent Test**: 可以通过添加源角色图片、调用 AI 生成、验证新图片来完整测试。

**Acceptance Scenarios**:

1. **Given** 草稿中有视频资源, **When** 用户拖拽视频到"源角色图片"区域, **Then** 从视频当前帧截取图片添加为源角色图片
2. **Given** 草稿中有源角色图片, **When** 用户选择图片并点击"生成新角色", **Then** 调用豆包 API 并显示生成进度
3. **Given** AI 图片生成完成, **When** 用户查看资源列表, **Then** "新角色图片"区域显示生成的图片

---

### User Story 5 - 视频合成 (Priority: P5)

用户可以将多个对口型新视频按顺序合成为一个完整的视频。

**Why this priority**: 视频合成是最终输出步骤，需要先完成前面的所有视频处理流程。

**Independent Test**: 可以通过添加多个对口型新视频、执行合成、验证输出视频来完整测试。

**Acceptance Scenarios**:

1. **Given** 草稿中有多个对口型新视频, **When** 用户调整视频顺序, **Then** 可以拖拽调整视频播放顺序
2. **Given** 视频顺序已确定, **When** 用户点击"合成", **Then** 系统将视频合并为一个完整视频并显示进度
3. **Given** 视频合成完成, **When** 用户查看资源列表, **Then** "合成新视频"区域显示最终视频

---

### User Story 6 - 资源文件管理 (Priority: P6)

用户可以通过拖拽方式添加资源文件，也可以右键打开任意资源所在的文件夹，方便直接管理文件。

**Why this priority**: 这是辅助功能，提升用户操作便利性，但不影响核心流程。

**Independent Test**: 可以通过拖拽文件添加、验证文件导入、打开文件夹来完整测试。

**Acceptance Scenarios**:

1. **Given** 应用打开, **When** 用户拖拽文件到应用窗口, **Then** 文件被添加到对应的资源类型中
2. **Given** 资源列表中有资源, **When** 用户右键点击资源选择"打开所在文件夹", **Then** 系统资源管理器打开该文件所在目录

---

### Edge Cases

- 用户尝试切分一个时长过短（小于1秒）的视频时，应提示无法切分
- 视频处理过程中应用意外关闭，重新打开后应显示处理中断状态并允许重新开始
- 拖拽非支持格式的文件时，应提示"不支持的文件格式"
- 豆包 API 配置缺失时，AI 功能应显示配置提示而非报错
- 豆包 API 调用失败时（网络错误、超时、配额用尽等），直接显示错误信息，用户可手动重试
- 处理超大视频文件（>2GB）时，应有内存管理策略避免崩溃

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 显示草稿列表，每个草稿显示名称和创建时间
- **FR-002**: System MUST 支持创建、重命名、删除草稿
- **FR-003**: System MUST 按类型分组显示资源：源视频、源角色图片、提示词、新角色图片、分镜源视频、分镜新视频、高清分镜新视频、对口型新视频、合成新视频
- **FR-004**: System MUST 支持文字资源（提示词）的显示和编辑
- **FR-005**: System MUST 支持图片资源的预览显示
- **FR-006**: System MUST 支持视频播放，包括播放/暂停、进度拖动、静音功能
- **FR-007**: System MUST 支持从视频截取当前帧作为图片资源
- **FR-008**: System MUST 集成 video_splitter 工具实现视频自动分镜切分
- **FR-009**: System MUST 集成 video_upscaler 工具实现视频高清化，支持单个和批量处理
- **FR-010**: System MUST 集成豆包 API 实现图生图功能
- **FR-011**: System MUST 支持多个视频按顺序合成为一个视频
- **FR-012**: System MUST 支持拖拽文件添加资源
- **FR-013**: System MUST 支持打开资源所在文件夹
- **FR-014**: System MUST 在长时间处理任务时显示进度
- **FR-015**: System MUST 将草稿数据持久化到本地文件系统
- **FR-016**: System MUST 使用任务队列顺序执行后台任务，一次只处理一个任务

### Key Entities

- **Draft（草稿）**: 一个完整的视频制作项目，包含名称、创建时间、所有关联资源
- **Resource（资源）**: 草稿中的单个文件，有类型（源视频、源角色图片、提示词等）、文件路径、创建时间
- **ProcessingTask（处理任务）**: 后台处理任务，有类型（切分、高清化、合成、AI生成）、状态（pending/processing/completed/failed）、进度

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能在3次点击内完成从打开应用到预览任意资源
- **SC-002**: 视频播放延迟在用户点击后1秒内开始播放
- **SC-003**: 文件拖拽添加在松开鼠标后2秒内完成导入并显示
- **SC-004**: 处理任务进度更新频率至少每2秒一次
- **SC-005**: 应用支持同时管理至少100个草稿而不出现明显卡顿
- **SC-006**: 单个草稿支持包含至少50个资源文件
- **SC-007**: 用户满意度：界面风格符合苹果设计规范（简洁、现代）

## UI Design Reference

界面设计文件：`pencil-new.pen`

### 界面布局结构 (1440×900)

- **左侧边栏** (280px)：
  - 应用 Logo "视频工坊"
  - 新建草稿按钮
  - 草稿列表（显示名称、时间、项目数）

- **中间资源面板** (自适应宽度)：
  - 标题栏：当前草稿名称 + 操作按钮（切分视频、批量高清化）
  - 资源分组区域（可滚动）：
    - 源视频
    - 源角色图片
    - 分镜源视频
    - 提示词（可编辑文本卡片）
    - 新角色图片
    - 分镜新视频
    - 高清分镜新视频（带完成状态标记）
    - 对口型新视频
    - 合成新视频（空状态 + 合成按钮）

- **右侧预览面板** (420px)：
  - 预览标题栏 + 打开文件夹按钮
  - 视频播放器（播放/暂停、进度条、音量、全屏）
  - 资源信息卡片（文件名、类型、时长、分辨率、文件大小）
  - 操作按钮（AI 高清化、截取帧、删除）

### 设计风格

- **配色**：浅色系，Apple 风格
  - 背景：#FFFFFF / #F8F8FA
  - 主色调：#007AFF（Apple Blue）
  - 成功状态：#34C759
  - 警告/合成：#FF9500
  - 危险/删除：#FF3B30
- **圆角**：8px（小）、12px（中）、16px（大）、24px（超大）
- **字体**：Plus Jakarta Sans（标题）、Inter（正文）
- **边框**：#E5E5EA，1px

## Assumptions

- 用户使用的系统已安装 FFmpeg（video_splitter 和 video_upscaler 依赖）
- 豆包 API Key 由用户在配置中提供
- 草稿数据存储在应用执行目录下的 `storage/` 文件夹，每个草稿对应一个子文件夹，采用 JSON 格式存储元数据
- 视频文件不复制到应用目录，仅存储文件路径引用

## Clarifications

### Session 2026-01-26

- Q: 草稿存储位置？ → A: 应用执行目录下 `storage/` 文件夹，每草稿一个子文件夹
- Q: 并发任务处理策略？ → A: 顺序执行（任务队列），一次只处理一个任务
- Q: 豆包 API 调用失败处理？ → A: 直接报错，用户手动重试
- Q: 支持的文件格式？ → A: 视频 (mp4, mov, avi)，图片 (jpg, png, webp)
